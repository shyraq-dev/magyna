# Мағына

Қазақ тіліндегі кітап оқу/жазу платформасы. Next.js 14 (App Router) +
Supabase (Postgres, Auth, RLS) негізінде, Vercel-ге деплойға дайын.

## Мүмкіндіктер

- Email/парольмен тіркелу және кіру (Supabase Auth)
- Telegram Mini App арқылы бір батырмамен кіру (initData HMAC растамасы)
- Push-notifications: жаңа кітап пен жаңа тарау шыққанда сөреге сақтаған оқырмандарға хабарлама (Web Push, VAPID)
- Мұқаба суреттерін жүктеу (Supabase Storage, `covers` bucket)
- Тарау мәтінін Markdown редакторымен жазу/өңдеу (құрал жолағы + алдын ала қарау, GFM қолдауы)
- Автосақтау: жазу барысында жоба браузерде сақталады, интернет үзілсе/бет жабылса қалпына келтіріледі
- Тарау мазмұны (table of contents): ## және ### тақырыптардан автоматты жасалады, басқанда сол жерге секіреді
- Профильді толтыру: аватар (қиып/crop жүктеу), пайдаланушы аты, есім, өзі туралы (bio), Instagram/TikTok/веб-сайт сілтемелері
- Оқу баптаулары («Aa» батырмасы): қаріп (4 нұсқа), қаріп өлшемі, жол аралығы, тема (ақ/сепия/қара) — таңдау браузерде сақталады
- Әкімші тақтасы: пайдаланушыларды іздеу және бұғаттау (3 күн/1 апта/мәңгі, Supabase Auth ban_duration арқылы), пікірлерге шағымдану + модерация кезегі (өшіру/елемеу)
- Бейджтер жүйесі: автоматты (SQL trigger арқылы) берілетін оқырман/автор белгілері, профиль бетінде көрінеді
- Дорама Hub: дорама каталогы (мұқаба, жанр, сипаттама, трейлер, сыртқы «Көру» сілтемесі) + әр дорама астында нақты талқылау топтары (тақырып ашу → жауаптар тізбегі, флэт пікірлер емес)
- Басты бет: тіркелмегендерге лендинг (жарнамалық), тіркелгендерге нақты фид — «Оқып жатырсыз» (прогресс-жолақпен), «Жаңа кітаптар», «Танымал дорамалар», барлығы көлденең scroll
- Тарау соңында лүпіл (like) басу — «Үздік автор» мен «Көп оқылатын туынды» бейджтеріне негіз болады
- Кітапқа 1-5 жұлдызша баға қою — орташа рейтинг пен «Оқырман таңдауы» бейджіне негіз болады
- Хабарландыру қоңырауы (🛎 + оқылмаған саны): жаңа тарау (сөреге сақтағандарға), тақырыпқа жауап, кітапқа пікір — барлығы SQL trigger арқылы автоматты жазылады
- Баптаулар бөлімі (`/baptaular`): профиль карточкасы + 7 бөлек бөлім (Тіркелгі, Сыртқы келбет, Оқу параметрлері, Құпиялық, Мәлімдеме, Жад, Көмек) — Бейін бетіндегі «Баптау» белгішесінен ашылады
- Жалғыз-әкімші жазушы моделі: тек `is_admin = true` профилі кітап
  жаза алады (`supabase/schema.sql` ішіндегі бірегей индекс арқылы
  дерекқор деңгейінде қорғалған)
- Кітаптар каталогы, тарау бойынша оқу беті
- Жеке сөре (сақтау/алу) және скролл негізіндегі оқу прогресі
- Пікірлер
- Құпиялық саясаты мен Пайдалану шарты беттері (`/baptaular/...`)

## Іске қосу

```bash
npm install
cp .env.example .env.local   # Supabase URL мен anon key-ді енгізіңіз
npm run dev
```

## Supabase баптау

1. [supabase.com](https://supabase.com) сайтында жаңа жоба жасаңыз.
2. SQL Editor-де `supabase/schema.sql` файлының мазмұнын іске қосыңыз.
3. Project Settings → API бөлімінен `URL` және `anon public key`
   мәндерін алып, `.env.local` файлына қойыңыз.
4. Өзіңізді жалғыз автор ету үшін, тіркелгеннен кейін SQL Editor-де:

   ```sql
   update public.profiles set is_admin = true where username = 'сіздің_атыңыз';
   ```

5. Auth → URL Configuration бөлімінде Site URL мен Redirect URL-ді
   (`https://<domain>/auth/callback`) енгізіңіз.

## Vercel-ге деплой

1. Репозиторийді GitHub-қа жүктеп, Vercel-де импорттаңыз.
2. Environment Variables бөлімінде `NEXT_PUBLIC_SUPABASE_URL` мен
   `NEXT_PUBLIC_SUPABASE_ANON_KEY` қосыңыз.
3. Deploy басыңыз.

## Telegram Mini App баптау

1. [@BotFather](https://t.me/BotFather)-тан бот жасаңыз (немесе barды пайдаланыңыз), одан `TELEGRAM_BOT_TOKEN`-ды алыңыз.
2. `/newapp` командасымен ботқа Mini App қосыңыз, Web App URL ретінде
   сіздің Vercel доменіңізді (`https://<domain>/kiru`) көрсетіңіз.
3. Supabase Project Settings → API бөлімінен `service_role` кілтін алып,
   `.env.local`-ге `SUPABASE_SERVICE_ROLE_KEY` ретінде қойыңыз (бұл
   кілтті ешқашан клиентке немесе GitHub-қа шығармаңыз).
4. Ботты Telegram-нан ашып, «Telegram арқылы кіру» батырмасын басыңыз —
   ол тек қолданба Telegram ішінде ашылғанда ғана көрінеді.

Механизм: `/api/auth/telegram` initData қолтаңбасын bot token арқылы
тексереді, `profiles.telegram_id` бойынша қолданушыны тауып/жасайды,
содан кейін Supabase-тің magic-link токенін генерациялап, клиент оны
`verifyOtp` арқылы толыққанды сессияға айналдырады — қолданушы email
немесе құпия сөз енгізбейді.

## Push Notifications баптау

1. VAPID кілттерін жасаңыз:

   ```bash
   npx web-push generate-vapid-keys
   ```

2. Шыққан кілттерді `.env.local`-ге қойыңыз:
   `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`
   (өз email-іңіз, мыс. `mailto:you@example.com`).
3. `public/icon.png` файлын өз логотипіңізбен ауыстырыңыз (хабарлама
   белгішесі ретінде қолданылады).
4. Оқырман «Менің сөрем» бетінде «Жаңа тарау хабарламаларын қосу»
   батырмасын басып, браузер рұқсатын береді.

Механизм: `/sw.js` service worker `push` оқиғасын тыңдайды.
Админ жаңа кітапты жариялағанда (`PublishToggle`) немесе жарияланған
кітапқа тарау қосқанда (`ChapterForm`) `/api/push/notify` шақырылады —
ол сервис-роль клиентімен сөреге сақтаған (немесе, жаңа кітап
жағдайында, барлық жазылған) оқырмандарды тауып, `web-push` арқылы
хабарлама жібереді. Жарамсыз болған жазылымдар автоматты өшіріледі.

## schema.sql қайта іске қосу туралы

Файл толықтай **қайта іске қосуға қауіпсіз** (idempotent) — әр
`create policy`-дың алдында `drop policy if exists` тұр, сондықтан
"policy already exists" қатесі енді шықпайды. Файлдың соңында
"permission denied for table X" қатесін түзейтін `grant` командалары
да бар (бұл — RLS-тен бөлек, кестеге қатысты негізгі рұқсат мәселесі).

Егер бұрын "policy already exists" қатесімен тоқтап қалған болса,
скрипт сол жерден әрі қарай ешқашан орындалмаған — яғни кейінгі
барлық баптаулар (bio бағандары, avatars bucket, badges, reports,
т.б.) әлі қосылмаған болуы мүмкін. Файлды қазір **толық** қайта
іске қосыңыз.

## Профильді өңдеу үшін

`schema.sql`-ды қайта іске қосыңыз (Supabase SQL Editor) — жаңа
`bio`/`instagram_url`/`tiktok_url`/`website_url` бағандары мен
`avatars` bucket-і, сонымен қатар `is_admin`-ді қорғайтын trigger
осымен қосылады. Бұрын қосылған дерекқорда бәрі `if not exists`
арқылы қауіпсіз түрде үстелінеді, деректер жоғалмайды.

## Бейджтер жүйесі қалай жұмыс істейді

Барлық есептеу **SQL trigger-лерде** орындалады (`schema.sql`), Next.js
кодында емес — сондықтан деректер қай арнадан өзгерсе де (админ панелі,
Telegram, болашақ мобильді қосымша) бірдей дұрыс есептеледі:

- **Белсенді пікір қалдырушы** — 10+ пікір (`comments` insert-те есептеледі)
- **Марафоншы** — соңғы 30 күнде 5 кітапты соңына дейін оқыды (тараудың
  соңғысында скролл 95%-ға жеткенде `reading_progress.finished_at`
  қойылады — бұл үшін `ChapterPage` жалпы тарау санын алдын ала алады)
- **Талғампаз оқырман** — сөресінде 10+ кітап (саналы таңдауды өлшейтін
  жуықтау ретінде әдейі сөре көлемі алынды, рейтинг саны емес)
- **Бестселлер** — авторлың кез келген кітабы 10+ оқырманның сөресінде
- **Үздік автор** — авторлың барлық тарауларының жиынтық лайк саны 50+
  (`chapter_likes` insert-те есептеледі)
- **Көп оқылатын туынды** — бір тарау 500+ рет ашылды (`chapters.views`,
  әр оқылымда `increment_chapter_views()` арқылы атомарлы өседі)
- **Оқырман таңдауы** — авторлың кез келген кітабы 10+ баға жинап,
  орташа 4.5+ рейтингке жетті (`book_ratings` insert/update-те есептеледі)
- **Негізін қалаушы** — `is_admin = true` болған кезде автоматты беріледі

Барлық 8 бейдж те енді нақты деректен автоматты есептеледі — каталогта
«жоспарда» деп қалғаны жоқ.

## Баптаулар бөлімі — не бар, не жоқ

ТЗ-да 7 блок сипатталған (Профиль, Сыртқы келбет, Оқу режимі, Құпиялылық,
Хабарламалар, Кэш/Offline, Ақпарат/Көмек). Нақты жасалғандары:

- **Хабарламалар**: 3 санатты қосу/өшіру (жаңа тарау, пікірлер, дорама
  жауаптары) — trigger-лер осыны нақты тексереді. «Түн режимі» (Quiet
  Hours) жоқ.
- **Сыртқы келбет**: Жарық/Қараңғы/Жүйелік тема таңдау бар, бірақ **тек
  негізгі қаптама** (navbar, footer, body фон) қараңғы режимге ілінген —
  әр бет толық жабдықталған жоқ. Екпінді түс (accent color) және тіл
  таңдау жоқ.
- **Құпиялылық және қауіпсіздік**: құпия сөзді жаңарту (email
  тіркелгілер үшін) және аккаунтты өшіру нақты жұмыс істейді. Активті
  сессиялар, 2FA, профильдің ашықтығы — жоқ (соңғысы үшін жалпыға ортак
  профиль беттері де жоқ, сондықтан бұл баптау мағынасыз болар еді).
- **Ақпарат және көмек**: FAQ (статикалық), қолдау хаты жіберу (нақты
  жазылады, `/avtor/qoldau`-да көрінеді), заң құжаттарына сілтеме,
  нұсқа нөмірі.
- **Кэш/Offline режим**: мүлдем жоқ — оффлайн жүктеу үлкен бөлек фича.

## Тарау мазмұны қалай жасалады

`lib/markdown/toc.ts` тарау мәтінінен `##`/`###` тақырыптарын тауып,
`rehype-slug` қолданатын дәл сол slugger-мен id жасайды — сондықтан
мазмұндағы сілтемелер render етілген тақырыптармен нақты сәйкес келеді.
Кемінде 2 тақырып болғанда ғана көрінеді.
